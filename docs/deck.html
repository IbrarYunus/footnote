The problem

The dangerous answer is the one that reads well.

"Chat with our documents" is the first thing most companies ask an LLM to do.

The usual build is a fixed pipeline: search once with the user's words, paste the results into a prompt. A two-part question gets half an answer.

And it fails quietly. The answer is fluent, and one sentence in it came from nowhere. Someone acts on that sentence.

One rule: an answer you cannot check is not an answer.

  • An agent plans the research: it picks queries, splits the question, retries.
  • It may use only what its tools returned.
  • Every claim carries a citation the API has validated.
  • One click shows the source sentence, highlighted in place.
  • When the documents do not cover it, it says so.

Verification

Click a claim. See the sentence.

Search results go back to the model one sentence per block. The API returns which result and which sentences each claim rests on, and checks them. The model cannot cite text that is not there.

Prompting a model to type "[1]" gives markers that look right and are sometimes wrong. This does not.

Abstention

"That is not in the documents."

The handbook has nothing on Christmas parties. The agent searched for a dress code, tried the party angle, then stopped. The answer says what is missing and cites the nearby material it did find.

The prompt explains why guessing is harmful rather than shouting "never". The eval set includes ten questions like this one.

Architecture

An agent loop over a search tool. No framework.

Agent loopClaude with two tools, max six turns. It chooses queries and when to stop.
⇄
search_handbookBM25 + vectors, weighted rank fusion. Top 5 it has not seen yet.
read_pageAll passages of one page, when a result is cut off.
→
Cited answerResults return as sentence blocks with citations on. Streams text + spans.
→
UIOne HTML file over Server-Sent Events. Also a CLI.
  • No vector database. 2 MB of vectors; a numpy multiply takes under a millisecond. Worth revisiting past a few hundred thousand passages.
  • Local embeddings. No second API key, no per-query cost, documents stay on the machine.
  • Hybrid search. Vectors miss exact terms; keywords miss paraphrase. Rank fusion needs no score calibration.
  • Headings travel with the passage. "You can carry over 240 hours" means nothing to search without "Annual leave".

Evaluation · answers

What is measured, and what is not yet.

Measured: the search tool, on 59 questions (previous slide), and the pipeline code, by unit tests in CI.

Built, not yet run: the agent eval. 59 answerable questions plus 10 the handbook cannot answer. A second model grades each answer as correct, partial, wrong or abstained.

No answer-quality numbers are claimed until that suite has run on the agentic version.

  • Was the right passage ever retrieved, across all searches?
  • Did the answer cite it?
  • What share of the answer text carries a citation?
  • Did it abstain on the unanswerable ones?
  • Searches per question, latency, cost.
